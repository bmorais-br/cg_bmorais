# AN-11387: Replace hardcoded beta dealer list with CSV-driven source and per-dealer adoption rate windows

## Background

Two hardcoded SPID strings currently live in the codebase:
- `DEALER_LIST` in `config.py` — all active beta dealers, used in every query
- `ORIGINAL_BETA_DEALER_LIST` in `queries.py` — launch cohort used only for adoption rate

Both are manually maintained and error-prone. The finalized CSV ("Competitive Insights _ Beta Dealer Sign Ups - Finalized Dealer List (DO NOT EDIT).csv") is now the source of truth. It tracks each dealer's program status via an Added/Removed column.

Loading the CSV at runtime is not viable in Snowflake (stage path instability, special characters in filename). Instead, a local generation script parses the CSV once and writes derived constants into a new `dealers.py` module. The script is re-run whenever the CSV changes.

The CSV lives in `dep_engagement_measurement/` alongside the Python files.

## Added/Removed column logic

| Value | Meaning | Start date |
|---|---|---|
| null | Original beta dealer | 2026-05-21 |
| "Added on M/D" | Added mid-program | Parse as 2026-M-D |
| "Removed on ..." | Churned out | Exclude from all lists |

## Files changed

### New: `generate_dealers.py` (local script, not deployed to Snowflake)

- Reads the CSV using `Path(__file__).parent / "filename.csv"` — CSV lives in the same directory
- Skips the 3 junk header rows
- Parses the SPID and Added/Removed columns
- Outputs the DEALER_LIST string and DEALER_DATES dict to stdout, ready to paste into dealers.py
- Re-run this script any time the CSV changes, then copy output into dealers.py

### New: `dealers.py`

- Contains DEALER_LIST and DEALER_DATES as hardcoded constants
- Generated by generate_dealers.py — do not edit by hand
- Header comment points back to the CSV as the source of truth and documents how to regenerate
- DEALER_LIST: comma-separated string of non-removed SPIDs (same format as current config.py)
- DEALER_DATES: dict mapping int SPID → ISO date string (e.g. {337667: '2026-05-21', 457298: '2026-06-15'})

### Modified: `config.py`

- Remove hardcoded DEALER_LIST string
- Import DEALER_LIST from dealers instead

### Modified: `queries.py`

- Remove ORIGINAL_BETA_DEALER_LIST constant
- Import DEALER_DATES from dealers
- In load_adoption_rate(): reference DEALER_DATES directly (not as a parameter, to avoid @st.cache_data hashability issues)
- Inject a SQL VALUES CTE (dealer_start_dates) mapping each SPID to its start date
- Replace the global 30-day window anchor with a per-dealer join against dealer_start_dates

## SQL change in load_adoption_rate()

Before:
- dealer list: ORIGINAL_BETA_DEALER_LIST (static cohort)
- 30-day window: anchored globally to '2026-05-21' for all dealers

After:
- dealer list: full DEALER_LIST (all non-removed dealers)
- new CTE: dealer_start_dates built from DEALER_DATES VALUES clause
- 30-day window: anchored per-dealer via join on dealer_start_dates

## Acceptance criteria

- DEALER_LIST reflects only non-removed dealers from the CSV
- Adoption rate denominator = all non-removed dealers
- Adoption rate 30-day window is anchored per-dealer to their individual start date
- No hardcoded SPID strings remain in config.py or queries.py
- dealers.py is clearly marked as generated — edits go through generate_dealers.py, not by hand
